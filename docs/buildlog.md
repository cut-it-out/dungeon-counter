- Agent behavior: Claude Code makes surgical edits only, runs tests right after every change, prefers explicit code over abstractions, asks instead of guessing when requirements are unclear, and presents 2-3 options with trade-offs before writing code when several patterns are valid. - Build log: `docs/buildlog.md` in the attributed voice. It is read at the start of every session and written at the end, as stated in CLAUDE.md (directed, Session 1).
- Game: a five-minute potion-stall shop-management challenge for a fictional client (Pocket Lantern Games): predictable customer rushes, two competing upgrades, net profit as the goal with a personal best. It replaced the idle sim after my playtest review (directed, Session 6). Brief in `docs/BRIEF_dungeon-counter-idle-sim.md`, palette in `docs/dungeon-counter-brand-palette.md`. - Stack & hosting: Phaser + Vite + TypeScript, Vitest for the economy; mobile portrait 390×844; Cloudflare Pages via Git integration; GitHub `cut-it-out/dungeon-counter` (proposed → accepted, Session 2).
- Economy: one product; deterministic customer arrivals at a calm interval with predictable rush windows; fixed-batch restock with a cooldown after each restock; two competing upgrades, Better Brews (+price per level) and Bigger Crates (+potions per crate at the same crate cost); 300 s of game time that pauses when hidden; pure TypeScript module driven by both Phaser and the headless runner (directed, Session 2; rushes, cooldown and Crates directed, Session 6). Optional `calmSpeedup`: each calm stretch is that factor times the previous one; absent = constant (directed, Session 8).
- Score: net profit = closing balance − `startCoins`, with a personal best per config; an upgrade bought late is a loss. Replaces GDD v3 §12.1's gross revenue (directed, Session 6). Medals: per-config profit thresholds in the config JSON, shown on the summary with the next threshold and on the title; `challenge-v5` bronze 900c / silver 1050c / gold 1200c, set from my v5 runs (directed, Session 11).
- Baseline: the challenge loop gets a new frozen baseline, `challenge-v1`, proposed by Claude Code without simulation; tuning goes in revisions: `challenge-v2` (= `challenge-v1` + `calmSpeedup` 0.85; directed, Session 8) and `challenge-v3` (my hand-made config: `calmSpeedup` 0.7, rushes 1.2 / 0.8 / 0.65 s; the default; directed, Session 9). - Dead-shop guard: an upgrade is blocked when even selling the whole shelf at the price after it could not fund a restock: `coins − cost + stock × priceAfter < restockCost` (Brews: `priceAt(level + 1)`; Crates: the price is unchanged). Reason text "Need 53c to stay stocked" shows the unlock amount (directed, Session 4; GDD v3 §15; both upgrades, Session 7).
